# DG-LAB 官方波形模板调研

> 状态：调研结论（2026-11-09）
> 目的：确认“只读 DG-LAB 官方模板”是否存在、从哪里获得、格式与授权
> 相关：`docs/脱离DGHub全链路评估.md`、`tools/v3_probe/`

---

## 0. TL;DR

**不存在**官方发布的、可整包分发的“波形模板库”。

官方波形只以零散形式存在：

| 来源 | 数量/内容 | 许可 | 能否随项目分发 |
|---|---|---|---|
| 官方协议仓库 `coyote/v3/example.md` | 2 条 V3 示例（呼吸 12 帧、潮汐 22 帧） | 无 OSS 许可；商业使用需事先授权 | 不宜 |
| 官方归档 Demo `dglab-websocket-simple` | 16 条 `.pulse` + `expectedV3` | 无 LICENSE；README 禁止未经授权商用 | 不宜 |
| 官方 SDK `dglab-kit` / `dglab-kit-python` | 24 条郊狼波形（`raw` 16 位 HEX） | GPL-3.0 | 仅 GPL 兼容项目 |
| DGHub 内置预设 | DGHub 自带只读库，部分与官方 16 条同名 | DGHub AGPL-3.0 | 导出不等于授权 |
| HD2-DG-LAB `waves.py` | 7 条自制解析式预设 | MIT（自制） | 可，但不是官方模板 |
| 社区 `pulse_data` | 用户/社区命名的 16 位 HEX 数组 | 各来源不一 | 需逐项确认 |

因此，“只读官方模板”不能简单理解成“随程序打包一套官方波形”。必须指定**来源、校验和、许可**，并在条件不满足时 **fail-closed**（模板模式禁用、输出归零，不回退自制/社区数据）。

## 1. 官方发布物到底有什么

### 1.1 官方协议仓库的 2 条 V3 示例

原 `DG-LAB-OPENSOURCE/DG-LAB-OPENSOURCE`，现 `dungeonlab-open/dglab-bluetooth-protocol` 的 `coyote/v3/example.md`，标题为 “Built-in App Pulses in V3 Format”：

- 呼吸：12 帧；
- 潮汐：22 帧；
- 仓库没有 LICENSE，明确“商业使用需事先授权”。

这两条适合做**协议/格式校验的 golden sample**，不足以覆盖 wows 的五类事件。

### 1.2 官方归档 Demo 的 16 条 `.pulse`

`dungeonlab-open/dglab-websocket-simple` 的 `socket/DG_WAVES_V2_V3_simple.js`：

- 16 条波形，字段 `name/raw/expectedV2/expectedV3`；
- 没有 LICENSE；README 写明“未经授权请勿用于任何商业用途”；
- 该文件的 `expectedV3` 已经是转换好的 V3 帧，优先用它，避免复刻未公开的滑块映射。

### 1.3 官方 SDK 的 24 条郊狼波形

`dglab-kit` / `dglab-kit-python` 内置：

- 24 条郊狼、20 条负鼠波形；
- `raw` 为 16 位 HEX 数组；
- GPL-3.0。

如果项目能接受 GPL-3.0，这是**来源最清晰、数量最完整**的“官方”波形集合；如果项目要闭源分发，则不能直接打包。

SDK 的模板数据结构、V3/V4 发送方式、循环/停止语义见 [`docs/官方SDK模板用法.md`](官方SDK模板用法.md)。

### 1.4 DGHub 内置预设

DGHub 里的“颗粒摩擦 / 连击 / 潮汐 / CS2-燃烧 / CS2-死亡”：

- 是 **DGHub 自带只读内置预设**，不是官方模板包，也不是用户库；
- 其中颗粒摩擦、连击、潮汐、心跳节奏与官方 16 条同名；**CS2-燃烧、CS2-死亡不在官方 16 条内**，属 DGHub 自制；
- 数据不在外部 JSON/DB，打包在 exe 的 `PYZ.pyz` 内；
- 运行时可通过 DGHub HTTP API 导出：
  - `GET /api/presets/export`（用户库整体）；
  - `POST /api/presets/export-pulse` `{name, device_family}`（选中项，含内置）；
  - `GET /api/pulse-presets`（列表）。
- DGHub 是 AGPL-3.0；导出数据不等于获得再分发许可。

### 1.5 HD2-DG-LAB 的预设

`hd2coyote/waves.py` 的 7 个预设（pinch/sting/buzz/ramp_up/breath/heartbeat/death）是 **HD2 自制解析式波形**；`wave_lib.py` 管用户命名波形并互导 `pulse_data` JSON。HD2 没有官方模板；它的价值是 V3 编码、限幅、100 单元/500 队列约束的参考实现，而不是模板来源。

## 2. `.pulse` 与 `pulse_data` 格式

### 2.1 `.pulse`

DGHub `WaveData.js` 的解析器把 `.pulse` 拆成：

```text
Dungeonlab+pulse:<rest>,<speed>,<unknown>=<freqA>,<freqB>,<duration>,<mode>,<enabled>/<strength-type>,...
```

- 小节用 `+section+` 分隔；
- `rest` 0–100 映射 0–10s；
- `speed` 1/2/4；
- `freqA/B` 0–83 是 App 滑块值，需经社区映射表转成 ms；
- `duration` 0–99；
- `mode` 1–4；
- 锚点 `强度0–100-类型0自动/1锚点`，每竖条 0.1s。

官方“呼吸”示例（只保留结构，不复制整段数据）：

```text
Dungeonlab+pulse:35,1,8=0,20,0,1,1/0-1,20-0,40-0,...
```

它的 `expectedV3` 前两项类似 `0A0A0A0A00000000`、`0A0A0A0A14141414`。

### 2.2 转 V3 帧

- 16 位 HEX = 8 字节 = 100ms；
- 前 4 字节：频率（10–240）；
- 后 4 字节：强度（0–100）；
- 频率 ms → 字节的社区映射：
  - 10–100：不变；
  - 101–600：`(v-100)/5 + 100`；
  - 601–1000：`(v-600)/10 + 200`；
- 强度按 25ms 网格采样锚点曲线；
- 任一强度 >100 或频率越界，App 会丢弃整个 100ms 单元。

**优先使用官方 Demo 的 `expectedV3`**，不要复刻未公开的滑块映射；只有用户导入 `.pulse` 时才需要 best-effort 解析。

### 2.3 `pulse_data`

社区格式（HD2 `wave_lib.py`）：

```json
{
  "pulse_data": {"名字": ["16位HEX", "..."]},
  "punish_time": {"名字": 2}
}
```

每项 100ms；非官方，不能算“官方模板”。

## 3. 授权与合规

| 来源 | 许可 | 对只读加载器的影响 |
|---|---|---|
| 官方协议仓库 / 归档 Demo | 无 OSS 许可；商用需授权 | 不宜随项目再分发；个人使用也要谨慎 |
| `dglab-kit` / `dglab-kit-python` | GPL-3.0 | 打包其代码/波形数据要求项目 GPL 兼容；仅运行时读取用户文件不传染 |
| `pydglab` | GPLv3 | 同上；DGHub V2 模式使用 |
| DGHub | AGPL-3.0 | 导出数据不等于再分发许可 |
| HD2-DG-LAB | MIT | 代码可复用；但其预设是自制，MIT 不能洗白第三方波形数据 |
| 社区 `pulse_data` | 各来源不一 | 逐项确认；不能默认可分发 |

## 4. 建议的只读加载器设计

### 4.1 支持的来源（按优先级）

1. **官方校验清单 JSON**（推荐）：
   ```json
   {
     "schema_version": 1,
     "source": "official-demo|dglab-kit",
     "commit": "...",
     "license": "GPL-3.0-only|unofficial-personal-use",
     "waves": [
       {"name": "...", "frames_v3": ["..."], "sha256": "..."}
     ]
   }
   ```
   数据取自官方 Demo 的 `expectedV3` 或 dglab-kit 的 `raw`；加载时校验 `sha256` 和帧格式。
2. **用户导入官方 `.pulse`**：best-effort 解析；只读；标注来源；不做编辑。
3. **用户导入 `pulse_data`**：标注“社区格式”，不算官方；默认禁用或需显式确认。
4. **DGHub `export-pulse` 结果**：标注“DGHub 导出”，不算官方；默认禁用或需显式确认。

### 4.2 fail-closed 规则

以下任一情况，模板模式禁用、输出归零，**不回退** HD2/DGHub/社区数据：

- 没有清单；
- 清单 `source`/`commit`/`license` 缺失；
- `sha256` 不匹配；
- 任一帧不是 16 位 HEX、频率越界、强度 >100；
- 许可不允许当前分发方式。

### 4.3 对 wows_coyote 的映射

- `base` → 官方基础/呼吸类模板（可循环）；
- `hit` → 官方短促模板（一次性）；
- `fire` / `flood` → 官方持续状态模板（可循环）；
- `death` → 官方死亡模板（一次性）；
- 火/水叠层只改强度，不换模板；
- 没有合适官方模板的事件只输出强度，不播放波形。

## 5. 结论

- **“官方模板库”不是现成发布物**；官方只有 2 条示例、16 条 Demo 波形、24 条 SDK 波形，且许可各异。
- 如果项目能接受 **GPL-3.0**：用 `dglab-kit` / `dglab-kit-python` 的 24 条郊狼波形做随包模板，是来源最清晰、维护最稳的方案。
- 如果项目要 **闭源分发**：不要打包官方/第三方波形；只发布加载器，让用户导入其合法持有的官方 `.pulse`/导出文件；fail-closed。
- 如果只是 **个人自用**：可以用官方 Demo 的 16 条或 DGHub `export-pulse`，但明确标注来源与不可再分发；这不算“官方模板库随包分发”。

**当前实现（Phase 2，分发方案 B）**：`standalone/official_templates.py` 已支持

- **随包 manifest**：`standalone/templates/official_manifest.json` 含 24 条
  `dglab-kit-python` commit `4cce771c0fd93d043f3e83bbb0467e4197cde62e` 的官方模板；
  项目以 GPL-3.0 分发，默认 `--templates bundled`；
- 从用户提供的 `dglab-kit-python` 源码直读（`--templates sdk`，可选）；
- 从带 `source/commit/license/sha256/waves[]` 的外部 manifest 加载；
  任一帧/校验/许可不合法整份拒绝；
- 空库 fail-closed：只输出强度，不播放波形；
- `.pulse` 直接转换未实现，官方 Demo 请走 `expectedV3`/manifest。

命令与默认映射见 `docs/官方SDK模板用法.md` 第 8 节。
